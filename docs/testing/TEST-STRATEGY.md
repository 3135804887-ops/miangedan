# 测试策略（TEST-STRATEGY）

| 字段 | 内容 |

## 1. 目的

定义面个蛋全部测试层级的方法、环境、数据规则与准入准出标准，支撑 PRD 的发布硬门槛：关键流程验收 100%、评分稳定性与专家一致率、禁止属性进入证据为 0、严重泄露/越权/重复扣费/证据丢失为 0。

## 2. 范围

单元、契约、集成、端到端、WebRTC 专项、混沌、性能、安全、无障碍、AI 评测与公平性测试；测试环境与合成数据管理。

## 3. 非目标

- 不替代 ACCEPTANCE-MATRIX 的逐需求用例清单，也不替代 RELEASE-CHECKLIST 的发布守门。
- 不定义供应商选型测试（属 Phase 0，见 RELEASE-CHECKLIST Phase 0 节）。
- 不引入真实用户数据到任何测试环境。

## 4. 测试金字塔与各层策略

### 4.1 单元测试（unit）

- 对象：评分算法（SCORING-SPEC 全部伪代码分支与 SC-EC-01~24）、状态机迁移表、账单秒级计量与冲正、权重边界校验、取整规则。
- 标准：核心算法行覆盖 100%；评分相关分支覆盖 100%。

### 4.2 契约测试（contract）

- 对象：`docs/api/openapi.yaml`（请求/响应/错误结构/幂等键/分页）、`docs/api/realtime-events.md`（事件字段/方向/幂等键）、`ai/schemas/*.json`（样例校验）、前后端契约。
- 标准：契约变更必须双向兼容或显式升版本；Schema 样例校验失败即构建失败。

### 4.3 集成测试（integration）

- 对象：Temporal 工作流（含故障恢复与重放）、证据账本管道（NFR-005）、支付回调（签名/重放/乱序/重复）、删除编排（数据库/缓存/索引/对象存储/备份/第三方进度）、额度预留与返还、机构授权撤回即时生效。
- 标准：所有异步链路具备"中断-恢复-不丢不重"用例。

### 4.4 端到端测试（e2e）

- 对象：US-01~US-08 全旅程（上传→校对→计划→会前检查→实时面试→评分→报告→练习/重试→复核→删除）。
- 硬规则：端到端必须走**真实实时数字人链路**（含测试数字人供应商沙箱），不允许用静态头像、预录视频或人工旁白替代（PRD Phase 1 要求）。
- 覆盖设备检查、3 分钟重连、降级询问、单活动设备与转移。

### 4.5 WebRTC 专项

- 弱网矩阵：丢包 {0%,5%,15%,30%} × 抖动 {0,50,150ms} × 带宽 {5Mbps,1Mbps,512kbps}。
- 指标：建连（NFR-007）、回应（NFR-008）、打断（NFR-009）、ASR（NFR-010）、口型（NFR-011）、画质（NFR-012，弱网优先音频连续）。
- 3 分钟重连边界：179 秒恢复成功、181 秒标记评估未完成。
- 移动 Web：语音与文字面试可用；复杂代码/白板提示推荐桌面或平板。

### 4.6 混沌与故障演练

- 场景：供应商断连（ASR/TTS/LLM/数字人分别与同时）、数据库主库故障、消息积压、单可用区故障（60s 接管）、区域级故障（RTO ≤30min，证据 RPO=0，其他 ≤5s）。
- 断言：不判失败、不丢证据、不计故障时段费用、状态可恢复到最后已确认回合。
- 频率：每季度恢复演练、每半年供应商/数据库/积压/区域演练（PRD 要求）。

### 4.7 性能测试

- 指标基线：NFR-001~NFR-016 全部；评分 P95 ≤60s、报告 P95 ≤120s、解析 P95 ≤60s、计划 P95 ≤120s。
- 容量：每数据区发布前完成预计峰值 2 倍的完整数字人并发压测；容量 70% 自动扩容与"停止新建+预约"保护策略验证。

### 4.8 安全测试

- 渗透与红队：提示注入（简历/JD/网页）、恶意文件（病毒/宏/压缩炸弹/伪装/解析器漏洞）、越权（IDOR/水平/垂直）、跨租户（用户/机构/数据区）、支付回调重放与重复扣费、破窗流程滥用、会话劫持（房间令牌）。
- 零容忍：严重泄露、越权、重复扣费、评分证据丢失任一项出现即阻塞发布。
- 供应链：SBOM、依赖与密钥扫描、SAST/DAST 纳入 CI。

### 4.9 观测与日志扫描

- 对象：结构化日志、追踪属性、指标标签与错误上报（OpenTelemetry 基线，TASK-005）。
- 红线：日志与追踪禁止记录简历正文、完整回答、令牌、原始媒体；监控使用匿名技术标识，
  禁止面试正文作为日志标签或追踪属性（SEC-032、PRD Observability and Operations）。
- 测试方法：`services/observability` 单测覆盖敏感键整值替换、JWT/Bearer/`sk-`/超长令牌值模式替换、
  生产强制 strict、属性白名单拒绝路径，并使用 `fixtures/synthetic/log-scan/sensitive-samples.json`
  合成样本断言日志输出零泄露（发布门禁）。
- 频率：发布时 CI 日志敏感数据扫描；月度运营对线上日志/追踪管道敏感数据扫描
  （SEC-032、PRIVACY-DATA-MAP）；发现正文进入日志/追踪按隐私事故分级处置。

### 4.9 无障碍测试

- WCAG 2.2 AA：自动化扫描 + 键盘走查 + 屏幕阅读器（中英文）+ 残障用户可用性测试。
- 重点：实时房间（字幕、文字模式、焦点管理）、雷达/图表文字等价、便利设置全流程。
- 该门槛为 Pre-Launch Hard Gate，未达标不得进入 Beta。

### 4.10 AI 评测（ai_eval）

- 黄金集：`ai/evals/datasets/` 合成中英文样例；每次提示词/模型/量表变更全量回归。
- 稳定性：同一回答与量表重复评分，95% 维度分差异 ≤3 分，及格结论一致率 ≥98%。
- 公平性：按语言、口音、岗位、年限、输入模式、便利设置切分评估差异；禁止属性进入证据比例 = 0。
- 规则类：新题不重复已通过原题 ≥95%；追问不越出确认范围 = 100%；交接包八类内容完整 = 100%。

### 4.11 专家盲评校准

- 流程：抽样评分证据包 → 独立专家盲评 → 比对（轮次通过结论一致率 ≥85%，维度分 MAE ≤10）→ 校准量表/锚点描述 → 版本化记录。
- 频率：Beta 前首次校准；每月评分稳定性与公平性复测；重大模型/量表变更后重新校准。

## 5. 测试环境

| 环境 | 用途 | 数据 | 备注 |
|---|---|---|---|
| dev | 单元/契约/开发联调 | 合成 | 供应商沙箱或录制回放 |
| staging | 集成/e2e/AI 评测 | 合成 | 类生产拓扑缩小版，每数据区独立 |
| prod-like（每区） | 压测/混沌/发布前验证 | 合成 | 与生产同拓扑；混沌窗口需审批 |

- 供应商策略：主用沙箱 API；录制回放（replay）用于确定性回归；不得用生产用户内容做回放。
- 状态机/计时类测试使用可注入时钟，禁止 sleep 等待。

## 6. 合成数据规则

1. 只使用 `fixtures/synthetic/` 中的材料或明确标记 `synthetic: true` 的新增材料。
2. 禁止：真实简历、真实手机号/邮箱/身份证、真实录音录像、真实公司机密、真实支付卡。
3. 测试账户使用专用域名（example 域）与支付沙箱测试卡。
4. 测试数据定期清理；prod-like 环境数据保留 ≤30 天。
5. 合成数据需覆盖：中英文、各输入模式、便利设置、缺失材料、故障注入、保护属性攻击样本（仅用于验证阻断，不用于评分）。

## 7. 关键规则

1. 无真实数据、无真实密钥、无静态头像替代数字人链路——三条硬规则。
2. 金钱、评分、证据、删除四类路径必须有幂等与并发测试。
3. 故障注入测试的通过判据永远包含"不判失败、不丢证据、不乱计费"。
4. 指标按地区、语言、输入模式、供应商、岗位族、版本切分，防止平均值掩盖局部退化。

## 8. 异常处理

- 环境不可用阻塞测试：升级 SRE；不得以"环境原因"跳过发布门槛用例。
- flaky 用例：隔离、限期修复、禁止静默删除（见 ACCEPTANCE-MATRIX 第 11 节）。
- 供应商沙箱与生产行为漂移：记录差异并对关键路径保留 replay 兜底。

## 9. 验证方式

1. 本策略每层策略在 CI/流水线中有对应阶段与报告。
2. 发布候选按 RELEASE-CHECKLIST 汇总本策略各层结果。
3. 每季度复核指标阈值与 PRD NFR 的一致性。
