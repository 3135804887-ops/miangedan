# 规范评审检查单（SPEC-REVIEW-CHECKLIST）

| 字段 | 内容 |
|---|---|
| 文档编号 | TEST-REVIEW-001 |
| 版本 | 0.1.0 |
| 追踪 | PRD-001 Stakeholder Sign-Off；IMPLEMENTATION_PLAN.md（规范评审待办）；AGENTS.md（评审责任） |

## 1. 目的

为十个评审角色提供针对性的 PRD + 研发规范评审检查单，驱动 Sign-Off 闭环：每项检查可回答"通过/不通过/需修改"，不通过项必须转化为修改任务或新的未决事项（OD）。

## 2. 范围

PRD-001 V1.0 与 v0.1.0 规范套件（架构、领域、API、AI、数据安全、设计、测试、配置、Schema、评测材料）的正式评审。

## 3. 非目标

- 不替代各角色的专业判断；检查单是最低覆盖，不是评审上限。
- 不处理发布阶段检查（见 RELEASE-CHECKLIST）。

## 4. 通用检查项（所有角色）

- [ ] 规范与 PRD 无冲突；发现冲突时已按"以 PRD 为准"修正并记录。
- [ ] 每项需求（US/FR/NFR）在 IMPLEMENTATION_PLAN 与 ACCEPTANCE-MATRIX 中双向可追踪。
- [ ] 评审意见全部转为任务（TASK）或未决事项（OD，含负责人/证据/门槛），无口头遗留。

## 5. 分角色检查单

### 5.1 Product Lead（产品负责人）

- [ ] 用户旅程与 US-01~US-08 在 SCREEN-SPEC 页面清单中完整落地，无缺失页面。
- [ ] 商业规则（免费 60 分钟、单项目包、Pro、加油包、退款）与 BILLING-STATE-MACHINE 一致。
- [ ] "评估未完成 ≠ 失败"在所有文档中一致表达，无被弱化为失败的路径。
- [ ] Out of Scope 清单未被任何规范文件重新引入。

### 5.2 Engineering Lead（工程负责人）

- [ ] SYSTEM-ARCHITECTURE 五大边界与 DEPLOYMENT 三区拓扑可实施、无单点依赖媒体进程。
- [ ] 状态机（项目/房间/计费）迁移表完整、幂等规则可实现；Temporal/LangGraph 职责无重叠。
- [ ] EPIC-01-INFRA-DESIGN 的目录结构、CI 门禁、区域 fail-closed 自检可落地。
- [ ] OpenAPI 契约满足幂等键、分页、错误结构、区域信息约定；71 个操作覆盖 US 全部动作。

### 5.3 AI / Scoring Lead（AI 与评分负责人）

- [ ] SCORING-SPEC 伪代码与 PRD 评分模型逐条一致；SC-EC-01~24 边界案例无遗漏关键边界。
- [ ] OD-07（取整）、OD-08（归一化）已确认结论与量表 YAML 一致；`min_coverage_ratio=0.5` 校准计划明确。
- [ ] HANDOFF-SPEC 八类必备内容、压缩规则与事实完整性校验可实现；不重复规则可度量（≥95%）。
- [ ] PROMPT-POLICY 四层隔离、结构化输出与阻断规则完整；提示词不可产出最终分数。
- [ ] 评测集（zh/en）覆盖：正常、文字模式、证据不足、ASR 修订、矛盾、重试、注入、保护属性、练习隔离、故障降级。

### 5.4 Design Lead（设计负责人）

- [ ] SCREEN-SPEC 每页含空/加载/失败/权限/恢复状态；错误文案四要素（影响、数据保留、可重试、计费/评分影响）齐全。
- [ ] DESIGN-SYSTEM 占位规范不阻碍开发；最终品牌视觉的决策时间与责任人明确。
- [ ] 面试房间功能布局满足 PRD 功能键要求且未绑定特定视觉。

### 5.5 Accessibility Lead（无障碍负责人）

- [ ] ACCESSIBILITY.md 覆盖 WCAG 2.2 AA 全部承诺项；中英文分别测试的计划明确。
- [ ] 便利设置枚举与 Schema 一致；便利设置不进入评分证据在评分规范中闭环。
- [ ] 雷达/趋势/匹配图均有文字等价；文字模式口语"未评估"不记零。

### 5.6 Security / Privacy（安全与隐私负责人）

- [ ] THREAT-MODEL 覆盖提示注入、恶意文件、越权、跨租户、供应商泄露、重放、重复扣费、破窗滥用。
- [ ] PRIVACY-DATA-MAP 数据流、第三方处理器与授权映射完整；默认不跨境与例外流程清晰。
- [ ] SECURITY-REQUIREMENTS 每条可验证；零容忍项（泄露/越权/重复扣费/证据丢失）守门机制落实。
- [ ] 保留矩阵（12 个月/30 天/删除级联）与数据模型一致；删除覆盖备份与第三方。

### 5.7 Legal / Compliance（法务与合规负责人）

- [ ] 年龄政策（16 岁、监护人同意、未成年不存原始音视频）在产品流程中可执行。

- [ ] 数字人角色库授权链要求（PHASE0-PROVIDER-EVALUATION 第 4 节）满足肖像/声音合规。
- [ ] OD-03 法律实施方案的工作分解与决策门槛明确。

### 5.8 Finance / Payments（财务与支付负责人）

- [ ] 计费单位（数字人活动秒）、不计费时段、预留与返还规则无歧义。
- [ ] 幂等与防重复扣费机制（订单/回调/预留/返还）可实现"重复扣费为 0"。
- [ ] 发票/收据/税费与区域定价配置（OD-02 前置）边界清楚。

### 5.9 QA / SRE

- [ ] ACCEPTANCE-MATRIX 64 项需求 × 正常+异常用例、层级标注完整；CI 覆盖校验可行。
- [ ] NFR-001~016 全部有可执行的测量方法（TEST-STRATEGY 性能与混沌章节）。
- [ ] RELEASE-CHECKLIST 各阶段退出条件可核验；P0 风险关闭证据要求明确。

## 7. 关键规则

1. "有条件通过"的条件必须转化为 TASK 或 OD 并指定负责人，否则视为不通过。
2. 评审发现的 PRD 级问题暂停相关实现，由需求发起人裁决，不自行解释。
3. 全部角色签字后，规范文档版本从 `draft_for_review` 升为 `approved`（配置类同步提升 status）。

## 8. 异常处理

- 评审意见冲突：提交需求发起人裁决；裁决结果写入 CHANGELOG 与决策登记。
- 签字后发现的规范缺陷：按变更流程（AGENTS.md 第 5 节）先更新追踪再修改。

## 9. 验证方式

- 本检查单全部角色签字完成 = 规范评审待办（README 当前状态第 3 项）关闭。
- 签字记录与评审意见归档于本文件（或链接的评审系统）。
