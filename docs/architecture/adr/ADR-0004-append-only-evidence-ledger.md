# ADR-0004：追加式面试证据账本

| 状态 | accepted |
| 日期 | 2026-08-01 |
| 决策人 | 技术负责人、AI/评分负责人、安全负责人 |
| 追踪 | PRD-001 架构决策 5、Key Data Entities（EvidenceItem/ScoreVersion/UsageLedger/AccessAudit）；NFR-005、NFR-006；FR-025、FR-039、FR-040；TASK-026、TASK-084 |

## 背景

PRD 要求：问题、实际播放内容、回答、修订、工具事件、评分和复核采用追加记录，纠正通过新版本实现，不覆盖历史。同时：

- 正式复核必须使用"相同不可变证据"（FR-025）；
- 后台禁止直接改分，系统性偏差只能停用版本并提供免费重试（US-08 规则 7）；
- 审计日志追加写入且管理员不可删除（US-08 规则 12）；
- 证据 RPO = 0（容灾规则）。

可更新存储无法满足"证据在评分后未被改写"的证明需求。

## 决策

建立**追加式证据账本**作为四类记录的唯一写入方式：EvidenceItem、ScoreVersion、UsageLedger、AccessAudit。

1. 只提供追加写入；纠正以新版本（`supersedes_*` 链接）或冲正条目实现。
2. 数据库层以权限与约束双重保证：业务角色无 UPDATE/DELETE 权限；物理删除仅删除编排（DSR 服务）在数据权利流程中执行并全程记录。
3. 每条记录携带内容散列；评分输入输出以 `evidence_snapshot_hash` 绑定，复核时校验一致。
4. 持久化时序：下一主问题前完成上一有效回答持久化（NFR-005）；写入跨可用区同步（RPO=0）。

## 理由

- 可证明性：分数可随时被独立重算验证，历史不可抵赖。
- 合规：删除请求的对象从"修改数据"变为"按编排删除/匿名化并记录"，语义清晰可审计。
- 简单性：无并发更新冲突，幂等重试天然安全（NFR-006）。

## 替代方案与拒绝原因

1. **常规可更新表 + 审计触发器**：触发器可被特权账号绕过；复核无法证明输入未被改写。拒绝。
2. **只记事件不重放状态（纯事件溯源）**：读模型重建成本高，报告与复核需要稳定快照；采用"追加记录 + 物化读模型"折中。部分拒绝。
3. **区块链/外部公证**：超出需求，运营复杂度高且区域合规不明。拒绝。

## 影响

- 正面：复核、审计、公平性复查、删除编排都有可信事实源；"禁止改分"成为结构性约束而非纪律。
- 代价：存储增长（接受：逐字稿等 12 个月保留到期删除）；查询需要物化读模型维护。
- 后续动作：账本表与权限约束实现（TASK-026、DATA-MODEL）；删除编排对接（TASK-083）。

## 验证方式

- 数据库测试：以业务角色执行 UPDATE/DELETE 必须失败。
- 复核测试：改动任何证据字节后散列校验失败，复核被拒绝并告警。
- 删除演练：删除任务完成后账本中目标记录物理消失且删除过程本身有审计记录。
