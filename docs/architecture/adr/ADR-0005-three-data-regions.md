# ADR-0005：三数据区隔离部署（cn / eu / intl）

| 字段 | 内容 |
|---|---|
| 状态 | accepted |
| 日期 | 2026-08-01 |
| 决策人 | 技术负责人、安全负责人、法务与隐私负责人 |
| 追踪 | PRD-001 架构决策 6、Data Regions、风险表（违法跨境 P0）；NFR-004；TASK-002、TASK-096；OD-03、OD-09 |

## 背景

PRD 要求建立中国、欧盟、国际三个相互隔离的数据域：

- 注册时按常住地区推荐并由用户确认；创建后不得静默迁移；
- 中国区内容不默认调用境外模型；欧盟区优先在欧盟境内处理；
- 备用和灾备系统位于同一法定数据区域；
- 合法跨境需求必须完成影响评估、适用合同、备案或安全评估和单独告知。

"全球一套 + 逻辑分库"无法满足"不默认跨境处理"与区域法律实施（OD-03）的要求。

## 决策

1. cn / eu / intl 三数据区各自**完整独立部署**全部链路（控制面、媒体面、AI、评分、账本、数据层、观测、备份），区域代码枚举 `cn/eu/intl`（OD-09，已于 2026-08-01 确认）。
2. 区域之间默认**无任何用户内容通路**：无跨区复制、无跨区模型调用、无跨区备份、无跨区账号数据读取。
3. 账户以 `data_region` 为硬归属；网关按区域路由并拒绝区域不匹配请求。
4. 每区独立的供应商白名单、密钥、模型版本注册表与发布流水线。
5. 任何未来跨境机制必须经 OD-03 法律实施方案批准，并以新 ADR 记录。

## 理由

- 合规：中国个人信息保护与出境规则、GDPR 数据本地化倾向、各区域未成年人与支付规则差异，只有物理隔离能给出清晰边界。
- 故障域：单区故障不扩散（Phase 3 退出条件）。
- 信任：数据区域是用户可见承诺（注册时确认），必须结构性兑现。

## 替代方案与拒绝原因

1. **单区多活 + 数据标签**：跨区链路天然存在，"不默认跨境"无法结构性保证；法律审计不可解释。拒绝。
2. **双区（境内/境外）**：欧盟与国际的规则差异（GDPR 优先境内处理）无法表达。拒绝。
3. **容灾允许临时跨区**：PRD 明确"备用和灾备系统位于同一法定数据区域"。拒绝。

## 影响

- 正面：合规边界清晰、故障域隔离、区域可按各自节奏验证与放量（Phase 3/4）。
- 代价：三套完整基础设施与运营成本；全球功能（如状态页）需按区聚合而非共享数据；无跨区全局账号视图。
- 后续动作：区域化 IaC 与部署守门（TASK-002）；区域间配置漂移检测；OD-03 关闭后复核本 ADR。

## 验证方式

- 部署守门：IaC 静态检查无跨区资源引用（网络、IAM、备份、供应商端点）。
- 演练：Phase 3 容灾测试证明单区故障不扩散、备用系统不跨境。
- 审计：季度核对密钥、供应商端点、备份位置的区域归属。
