# ADR-0001：业务工作流与 AI 决策图分离（Temporal / LangGraph）

| 字段 | 内容 |
|---|---|
| 状态 | accepted |
| 日期 | 2026-08-01 |
| 决策人 | 技术负责人、AI 负责人 |
| 追踪 | PRD-001 架构决策 2；NFR-003、NFR-005、NFR-006；TASK-004、TASK-017、TASK-032 |

## 背景

面个蛋同时存在两类性质完全不同的"流程"：

1. **确定性业务长流程**：解析、计划、轮次推进、评分审核、解锁、报告、计费、删除编排。要求跨故障恢复、超时、重试、幂等、可审计（NFR-005/006，恢复规则）。
2. **概率性 AI 决策**：面试官内部的覆盖点推进、动态追问、打断判断、交接上下文组织。输出不可完全预演，需要检查点与人机回路，但绝不能直接改变业务状态。

若用同一套机制承载两类流程，要么业务状态被概率性输出污染，要么 AI 决策被业务事务束缚而牺牲实时性。

## 决策

业务工作流一律由 **Temporal** 承载（Go/Python worker，区域命名空间）；面试官内部决策一律由 **LangGraph** 图承载（Python AI 服务）。两者边界：

- LangGraph 节点只能通过明确定义的事件/证据写入与 Temporal 工作流交互；**LLM 无权直接改变业务状态**（分数、解锁、额度、状态机迁移）。
- Temporal 不感知追问内容语义，只消费结构化结果（覆盖点完成、回合完成、证据引用）。

## 理由

- Temporal 提供持久化执行、定时器（如 3 分钟重连窗口）、重试与幂等语义，直接满足 NFR 与恢复规则。
- LangGraph 提供图状态、条件路由与检查点，适合表达"覆盖点 → 追问 → 打断 → 下一覆盖点"的会话决策。
- 分离后可独立灰度、回滚与评测：AI 图版本退化不危及业务正确性（US-08 场景 6）。

## 替代方案与拒绝原因

1. **全部用 Temporal（含追问编排）**：追问延迟受工作流调度影响，难以满足 NFR-008（P50 ≤1.5s）；且把概率性逻辑塞进持久工作流会放大回放不确定性。拒绝。
2. **全部用 LangGraph（含计费/解锁）**：图检查点不提供业务级幂等与审计语义；LLM 输出直接影响金钱与解锁违反 PRD 安全原则。拒绝。
3. **自研状态机 + 直接 LLM 调用**：重复建设可靠性基础设施，故障恢复与审计成本不可控。拒绝。

## 影响

- 正面：业务正确性（幂等/恢复/审计）与 AI 体验（低延迟/可演进）各自最优；故障域清晰。
- 代价：两套运行时与心智模型；需要维护事件契约（`docs/api/realtime-events.md`）与边界守护测试。
- 后续动作：建立 AI 编排 → 控制面的允许事件白名单；架构守护测试禁止 AI 服务 import 业务写路径。

## 验证方式

- 守护测试：AI 服务代码中不存在对业务数据库/计费接口的写调用。
- 故障演练：LangGraph 服务整体宕机时，Temporal 工作流保持状态并按故障路径处理（不丢证据、不判失败）。
