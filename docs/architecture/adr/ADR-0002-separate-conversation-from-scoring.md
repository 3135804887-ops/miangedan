# ADR-0002：对话模型与评分服务分离

| 字段 | 内容 |
|---|---|
| 状态 | accepted |
| 日期 | 2026-08-01 |
| 决策人 | AI/评分负责人、技术负责人 |
| 追踪 | PRD-001 架构决策 3、Scoring Principles；FR-021、FR-025；TASK-040、TASK-043 |

## 背景

PRD 规定：问题生成模型只能提交证据，不能直接写最终分数；评分服务使用冻结的量表、权重和证据独立计算，支持重复运行和正式复核。如果对话模型（面试官）同时产出分数，则：

1. 分数无法与提问过程的利益脱钩（模型可能"手下留情"或"追问诱导"）；
2. 无法用完全相同的冻结输入重算（正式复核与稳定性回归不可行）；
3. 分数责任链（模型/提示词/量表/证据/计算版本）无法完整归因。

## 决策

面试官（对话）与评分是**两个独立服务边界**：

- 面试官只向证据账本提交证据（问题实际播放内容、回答、修订、工具事件）。
- 评分服务只读取 `ScoringInput`（冻结证据 + 冻结量表 + 冻结权重），按 `docs/ai/SCORING-SPEC.md` 计算并追加 `ScoreVersion`。
- 正式复核服务复用同一评分入口，校验证据散列后重算；任何角色不得直接编辑分数。

## 理由

- 可重复性：同一输入永远同一结论，支撑 95%/3 分、98% 一致率的发布硬门槛。
- 可归因：每个 ScoreVersion 关联模型、提示词、量表、权重、证据散列与计算版本。
- 可信：对话与评分的激励分离，符合结构化面试与证据评分原则（PRD 附录评分参考）。

## 替代方案与拒绝原因

1. **面试官模型直接打分**：违反 PRD 明文规则；无法复核与归因。拒绝。
2. **评分作为面试官图的一个节点**：图内评分会被会话上下文污染，且难以冻结输入。拒绝。
3. **规则引擎硬编码评分**：锚点判定需要语义理解，纯规则无法覆盖；但评分服务内部可用"模型判锚 + 确定性聚合"组合（聚合部分必须确定性）。部分拒绝，保留确定性聚合。

## 影响

- 正面：评分可复核、可回归、可归因；对话模型迭代不直接冲击分数稳定性（经灰度与回归守门）。
- 代价：需要维护证据冻结与散列机制；评分延迟进入用户体验路径（NFR-013 P95 ≤60s 约束）。
- 后续动作：证据散列与冻结点实现（TASK-026）；复核入口与"每次尝试一次"约束（TASK-043）。

## 验证方式

- 单元/契约：同一 ScoringInput 重复评分结果一致（稳定性回归 TASK-045）。
- 守护测试：面试官图无任何写 ScoreVersion 的路径；后台无改分接口（US-08 场景 3）。
