# 密钥轮换运行手册（KEY-ROTATION-RUNBOOK）

| 字段 | 内容 |
|---|---|
| 文档编号 | OPS-KEY-001 |
| 版本 | 0.1.0（2026-08-01，TASK-006） |
| 追踪 | SECURITY-REQUIREMENTS SEC-012、SEC-013、4.7 密钥轮换周期表；TASK-006 |
| 适用 | 全部数据区（cn/eu/intl）；密钥按区域独立轮换，禁止跨区复用 |

## 1. 目标

密钥轮换**不中断服务**：任一密钥类别按 4.7 周期表到期即轮换；疑似泄露立即轮换并吊销受影响令牌。
仓库、配置、日志、后台零明文；真实值只存在于密钥管理系统（SEC-012）。

## 2. 通用流程（五步）

1. **准备**：在密钥管理系统创建新版本（`kms_name` 所在区），记录版本号。
2. **过渡**：支持双读/双写的密钥（字段加密密钥、OTP pepper）先并行；其余直接切换引用。
3. **切换**：更新服务引用（`*_REF` 指向新版本），滚动发布，观测错误率与审计日志。
4. **验证**：运行 `python tools/secret-rotation/rotation_drill.py` 与
   `python tools/validate_docs.py --suites key-mgmt`；抽样验证新密钥可用、旧版本无活跃引用。
5. **退役**：过渡期结束后吊销旧版本，写审计记录（谁、何时、何密钥、何区域）。

## 3. 分类要点（周期与责任人见 SECURITY-REQUIREMENTS 4.7）

| 密钥类别 | 过渡方式 | 注意 |
|---|---|---|
| 身份签名密钥 `IDENTITY_SIGNING_KEY_REF` | 直接切换 | 旧签发 token 按缓存 TTL 自然过期；泄露即换 |
| 字段加密密钥 `DB_FIELD_ENCRYPTION_KEY_REF` | 双写过渡 | 新写用新密钥；旧数据按批次重加密后退役 |
| 数据库/对象存储凭证 | 双读过渡 | 先部署新凭证再移除旧凭证 |
| 支付回调验签密钥 | 直接切换 | 按供应商回调窗口保留旧密钥短期 |
| 供应商 API 密钥 | 直接切换 | 熔断期间或供应商事件后立即执行 |
| OTP pepper `EMAIL_OTP_PEPPER_REF` | 双写过渡 | 散列验证需同时接受新旧 pepper |

## 4. 演练与审计

- CI 阶段 1 `key-mgmt` 套件每次 PR 执行契约演练（REF 模式、区域配置一致、无明文）。
- 轮换演练记录入审计（SEC-013 验证方式：轮换演练不中断服务）。
- 发现密钥疑似泄露：按 SECURITY-REQUIREMENTS 7 异常处理，立即轮换并按 SEV 分级响应。
