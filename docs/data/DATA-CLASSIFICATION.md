# 数据分类（DATA-CLASSIFICATION）

| 字段 | 内容 |
|---|---|
| 文档编号 | DATA-003 |
| 版本 | 0.1.0（已批准 2026-08-01 规范评审） |
| 追踪 | PRD-001 "Privacy, Security & AI Governance → Security Controls"；US-01 规则 4；US-08 规则 1/9；FR-003、FR-039 |
| 一致性锚点 | `docs/data/DATA-MODEL.md`（存储位置）、`docs/data/RETENTION-MATRIX.md`（保留期）、`docs/security/SECURITY-REQUIREMENTS.md`（控制项）、`config/safety/policy.yaml`（保护属性） |

## 1. 目的

建立四级数据分类与各级处理规则，使加密、访问授权、日志脱敏、第三方共享与出境限制都有统一依据；明确敏感字段清单及其"隔离存储、不进入面试上下文"的规则。

## 2. 范围

平台处理的全部数据类别：用户内容、证据与评分、商业数据、机构数据、运营与审计数据、公开内容。

## 3. 非目标

- 不逐表重复字段清单（见 DATA-MODEL）；本文给分类与处理规则。
- 不替代法律评估（OD-03）；分类是工程控制基线。

## 4. 分类定义与映射

| 级别 | 定义 | 示例 |
|---|---|---|
| `restricted` | 泄露会直接造成严重个人损害或法律责任的原始个人内容 | 原始简历/JD 文件、逐字稿、回答文本（含 ASR 原文与修订文本）、原始音视频（授权后）、敏感身份字段（电话/邮箱/证件/详细地址/照片）、支付凭证与卡信息 |
| `confidential` | 与用户个人强关联的结构化数据，泄露会造成明显损害 | 结构化简历/JD 画像、评分与报告、逐题证据、授权记录、机构任务个人状态、账户资料、使用账本 |
| `internal` | 不含个人内容的运营数据 | 匿名技术指标（延迟、错误率、容量）、≥10 人聚合分析、供应商健康数据、版本注册表 |
| `public` | 公开内容 | 营销页面、公开帮助文档、状态页、品牌素材 |

## 5. 各级处理规则

| 控制项 | restricted | confidential | internal | public |
|---|---|---|---|---|
| 存储加密 | 静态加密 + 字段级独立密钥 | 静态加密 | 静态加密 | 无特殊要求 |
| 密钥 | 独立密钥（DB_FIELD_ENCRYPTION_KEY_REF），定期轮换 | 区域主密钥 | 区域主密钥 | — |
| 访问授权 | 用户本人；客服/后台仅经用户针对会话授权或破窗流程（双人审批+通知+审计） | 用户本人；机构按任务细粒度授权；运营默认脱敏 | 运营角色只读 | 任何人 |
| 日志/追踪 | 正文、令牌、媒体**禁止**入日志与追踪属性 | 禁止入日志（可记录 ID 与计数） | 可记录 | 可记录 |
| 传输 | TLS；媒体面 SRTP/DTLS | TLS | TLS | TLS |
| 出境 | 禁止（区域硬隔离；合法跨境须影响评估+合同+备案/安全评估+单独告知） | 同左 | 区域内优先；匿名聚合经评审可跨区汇总 | 无限制 |
| 第三方共享 | 仅处理必需的最小集（如 ASR 语音流），DPA + 不保留承诺；支付 PCI 范围最小化 | 不出售；不提供雇主筛选 API | 可按合同共享 | 自由 |

## 6. 敏感字段清单与隔离规则

以下字段类别为 restricted 中的特别管控类，**只存在于隔离存储，绝不进入面试上下文**（问题生成、评分、交接、报告、日志、机构视图）：

| 字段类别 | 存储位置 | 面试上下文规则 |
|---|---|---|
| 电话号码 | 隔离字段（加密） | 排除（resume_versions.profile_json 不含） |
| 邮箱 | 隔离字段（加密）；登录身份另存 identities | 排除 |
| 证件号码 | 隔离字段（加密） | 排除 |
| 详细地址 | 隔离字段（加密） | 排除 |
| 照片 | 原始文件内；不提取 | 排除；禁止面部/外貌分析 |
| 性别、婚育状况 | 不主动收集；简历中出现则隔离 | 排除；属保护属性 |
| 年龄相关（出生日期） | 仅年龄状态推导（age_status），不存完整出生日期 | 排除；年龄本身为保护属性 |
| 情绪/微表情/人格推断 | 不产生此类数据 | 禁止产生（产品规则） |

保护属性全集见 `config/safety/policy.yaml` protected_attributes；其进入评分证据的目标比例为 0（发布硬门槛）。

## 7. 关键规则（红线）

1. restricted/confidential 正文永不进入日志、指标标签、追踪属性、错误上报。
2. 敏感字段隔离：解析管道在结构化阶段即剥离，剥离结果只记录类别（`excluded_sensitive_fields`）不记录值。
3. 机构默认不可见 confidential 个人内容；聚合分析 <10 人不展示。
4. 出境限制适用于 restricted 与 confidential；备份与灾备同样受区域约束。

## 8. 异常处理

| 异常 | 处理 |
|---|---|
| 解析管道疑似漏剥敏感字段 | 结构化校验器命中模式（手机号/邮箱/证件号）→ 阻断入库 + 告警 |
| 日志扫描发现 restricted 内容 | 安全事件：清除日志、轮换可能暴露的令牌、复盘脱敏规则 |
| 分类争议（新数据类型） | 按更严格级别先行处理，安全/隐私评审后定级 |

## 9. 验证方式

1. CI 敏感字段扫描：fixtures 与评测数据不含真实 PII；日志样例不含 restricted 内容。
2. 渗透测试：restricted 数据访问路径全部需授权且写审计。
3. 数据地图核对：每类 restricted/confidential 数据在 PRIVACY-DATA-MAP 中有流向与处理器记录。
