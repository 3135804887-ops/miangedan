# 计费状态机（BILLING-STATE-MACHINE）

| 字段 | 内容 |
|---|---|
| 文档编号 | DOMAIN-003 |
| 版本 | 0.1.0（已批准 2026-08-01 规范评审） |
| 追踪 | PRD-001 US-06、Commercial Model；FR-031 ~ FR-033；NFR-006（幂等）；风险表（额度/支付故障 P1） |
| 一致性锚点 | `docs/domain/INTERVIEW-STATE-MACHINE.md`（额度联动点）、`docs/api/openapi.yaml`（接口）、`docs/data/DATA-MODEL.md`（账本表） |

## 1. 目的

定义报价、额度预留、秒级计费、暂停、完成、释放、故障返还、退款、重复回调与订阅到期的确定性行为，保证：**重复扣费为 0**、**余额不足不得中断已开始的正式轮次**、**系统故障自动全额返还**。

## 2. 范围

- 权益模型：免费 60 分钟数字人额度、单次项目包、Pro 订阅、时长加油包。
- 报价（Quote）、订单（Order）、额度预留（Reservation）、使用账本（UsageLedger）、退款（Refund）、订阅生命周期。
- 支付回调的签名验证、重放防护与幂等处理。

## 3. 非目标

- 不定最终定价（未决事项 OD-02）。
- 不定义税务/发票的法定细节（按区域法律实施方案 OD-03 落地）。
- 不定义机构合同结算条款（仅定义机构额度消耗的平台侧规则）。

## 4. 核心常量与单位

| 项 | 规则 |
|---|---|
| 计费单位 | 秒（数字人音视频已连接且正式面试处于 LIVE 的实际秒数） |
| 不计费时段 | 生成、评分、报告等待、故障暂停（PAUSED_SYSTEM）、重连窗口（RECONNECTING）、AUTH_PAUSED、降级后的文字面试（自故障点起） |
| 用户主动用文字回答 | 数字人正常运行时仍计数字人时间 |
| 免费额度 | 首次登录获得 60 分钟数字人额度；含个性化计划、正式面试、完整报告与一次练习 |
| 单项目包 | 覆盖已确认 1–5 轮首次正式面试 + 每个失败轮次的一次正式重试 |
| Pro 订阅 | 月度时长 + 重试权益；未使用时长最多结转一个账期；总余额 ≤ 月度额度 2 倍 |
| 预留规则 | 每轮开始前预留足够额度；不足则阻止开始并提供购买；面试中禁止弹出续费/广告/余额不足 |

## 5. 状态机

### 5.1 报价（Quote）

```
QUOTE_DRAFT → QUOTE_PRESENTED → QUOTE_ACCEPTED（随 plan.confirmed 冻结）
     ↑              ↓
     └── 计划修改（开始前）→ QUOTE_RECALCULATED → QUOTE_PRESENTED
```

- 报价组成：轮次数、时长、数字人规格、包含的正式重试、税费、有效期。
- 第一轮开始前修改计划 → 重新报价；增加轮次/时长只付差额；减少配置释放未使用额度。
- 开始后：简历、JD、轮次、权重与**计费版本**冻结，不再重新报价。

### 5.2 订单（Order）

```
ORDER_CREATED → PAYMENT_PENDING → PAID
     │               │→ PAYMENT_FAILED（保留计划，可重新支付）
     │               └→ PAYMENT_TIMEOUT → PAYMENT_PENDING（保持处理中，禁止重复扣款）
     └→ ORDER_CANCELLED（未支付主动取消）
```

幂等与防重：

1. 创建订单携带用户侧幂等键；重复创建返回同一订单。
2. 支付回调必须验签 + 时间戳重放窗口校验 + `payment_event_id` 去重；同一 `payment_event_id` 重复回调只处理一次。
3. 支付成功未到账：订单保持 PAYMENT_PENDING，对账任务按支付侧流水号收敛；**同一订单只记一次权益和一次扣款**。
4. 检测到重复扣款（同一订单两笔成功扣款）：自动识别并原路退回，写 Incident 并通知用户。

### 5.3 额度预留与秒级账本（Reservation / UsageLedger）

```
RESERVATION_CREATED（每轮开始前）→ CAPTURING（会话 LIVE，秒级累计 billable_seconds）
   │                                 │→ PAUSED（故障/重连/认证暂停；不计秒）
   │                                 │→ SETTLED（轮次正常结束：结算实际使用，多余预留释放）
   │                                 └→ REFUNDED_FULL（系统责任导致 EVALUATION_INCOMPLETE：
   │                                       自动全额返还本轮预留，账本记录原因）
   └→ RELEASED（轮次未开始而取消/减少配置，释放未使用预留）
```

账本规则：

1. UsageLedger 追加式；返还与释放以冲正条目实现，不修改原条目。
2. 每条记录：项目、轮次、开始/结束时间、使用秒数、类型（预留/消费/释放/返还/退款）、原因、余额快照。
3. 用户可查看逐笔账单（FR-033）。
4. 预留保证：已开始的正式轮次**不**因余额变化中断；余额校验只发生在每轮开始前。

### 5.4 退款（Refund）

```
REFUND_REQUESTED → REFUND_REVIEWING（大额或人工补偿：双人审批）→ REFUND_APPROVED → REFUNDED
                 ↘ REFUND_REJECTED（说明原因；用户可申诉）
```

- 系统故障造成未完成：自动返还本轮全部预留额度；用户可选择重试或退款。
- 未使用项目按适用地区规则退款；大额退款或人工补偿双人审批。
- 退款、付费状态和争议**不得**影响评分、复核或解锁。

### 5.5 订阅（Subscription）

```
SUB_ACTIVE → SUB_CANCELLED（用户取消续费；权益保留至账期结束）→ SUB_EXPIRED
           → SUB_EXPIRED（到期未续）
  特别规则：账期结束时刻若正式面试进行中 → 当前轮正常结束；后续轮次开始前再校验权益
```

- 自动续费单独勾选并在扣款前提醒；续费价格或权益变化必须提前通知并重新同意。
- 到期不删除历史，不影响导出或删除权利。
- 结转：未使用时长最多结转一个账期；总余额 ≤ 月度额度 2 倍（超出部分不结转）。

## 6. 与面试状态机的联动点

| 面试事件 | 计费行为 |
|---|---|
| `round.started` 前置 | RESERVATION_CREATED；不足则阻止开始并提供购买 |
| `avatar.ready` / 会话 LIVE | CAPTURING 开始（`usage.meter.started`，幂等） |
| PAUSED_SYSTEM / RECONNECTING / AUTH_PAUSED / DOWNGRADE_PROMPTED | 计量暂停（`usage.meter.stopped`，幂等） |
| `avatar.downgrade_accepted` | 自故障点起不再消耗数字人额度 |
| `round.ended` | SETTLED：按实际秒数结算，多余预留释放 |
| 系统责任 → EVALUATION_INCOMPLETE | REFUNDED_FULL：自动全额返还本轮预留 + 重试/退款入口 |
| 用户主动退出 | 按实际使用扣减（SETTLED），不返还 |

## 7. 区域化规则

- 中国区：人民币、本地支付、合规发票；国际区：主要银行卡、本地货币、税费展示与收据。
- 按购买力、税费与本地成本定价，不做简单汇率换算（定价数值属 OD-02）。
- 支付供应商凭证按数据区隔离配置（见 `.env.example`）；浏览器不持有支付密钥。

## 8. 关键规则（红线）

1. 重复扣费为 0：订单、回调、预留、返还全部幂等。
2. 已开始的正式轮次不因余额不足中断；余额校验只在轮次开始前。
3. 系统责任故障：不扣数字人时长，自动全额返还本轮预留。
4. 付费状态永不改变评分、复核、隐私、无障碍与故障恢复规则。
5. 账本追加式；任何"修改历史账目"需求以冲正条目实现并写审计。

## 9. 异常处理

| 异常 | 处理 |
|---|---|
| 支付回调重复/超时/状态不明 | 验签+去重；保持 PAYMENT_PENDING；对账收敛；不产生二次扣款 |
| 预留时额度竞态（并发开始两轮） | 单活动设备锁 + 预留原子化；后到请求收到额度冲突错误 |
| 结算时账单服务不可用 | 计量事件先入区域事件流持久化；恢复后重放结算（不丢秒数） |
| 重复扣款被发现 | 自动原路退回 + Incident + 用户通知 |
| 退款审批超时 | 工单升级；用户可见真实进度 |

## 10. 验证方式

1. 单元/集成：全部状态迁移与幂等键测试；重复回调、超时、乱序回调无副作用。
2. 并发测试：并发预留、并发支付回调、设备转移中的计量一致性。
3. 故障演练：账单服务中断后重放结算不丢不重；故障返还自动化校验。
4. 验收：US-06 场景 1–5 全部通过；重复扣费压测与混沌测试结果为 0。
