# 安全需求（SECURITY-REQUIREMENTS）

| 字段 | 内容 |
|---|---|
| 文档编号 | SEC-REQ-001 |
| 版本 | 0.1.0（已批准 2026-08-01 规范评审） |
| 追踪 | PRD-001 "Security Controls"、Risks & Mitigation、NFR（Accessibility and Security）；US-08；FR-037 ~ FR-040 |
| 一致性锚点 | `docs/security/THREAT-MODEL.md`（威胁到控制的映射）、`docs/security/PRIVACY-DATA-MAP.md`、`docs/data/DATA-CLASSIFICATION.md`、`.env.example` |

## 1. 目的

将 PRD 的安全控制条款转化为可执行、可验证的安全需求清单（SEC-001…），每条含验证方式，作为开发、评审与上线守门依据。

## 2. 范围

身份与访问、加密与密钥、应用与供应链安全、文件安全、审计与监控、隐私工程、事件响应、区域隔离、治理与合规对齐。

## 3. 非目标

- 不重复威胁建模过程（见 THREAT-MODEL）。
- 不定义具体厂商/工具选型（属 EPIC-01 实施决策）。
- 不提供法律意见（区域法律实施属 OD-03）。

## 5. 事件响应

### 5.1 事故分级与时限

| 级别 | 定义 | 响应时限 | 通报 |
|---|---|---|---|
| SEV-1 | 严重数据泄露、越权访问、重复扣费、评分证据丢失（**零容忍项**） | 立即响应（≤15 分钟集结） | 状态页 + 受影响用户 + 依法监管通报 + 事后公开复盘 |
| SEV-2 | 核心流程不可用、评分/支付错误（未泄露） | ≤30 分钟 | 状态页 + 客服预案 |
| SEV-3 | 局部功能退化、有变通方案 | ≤2 小时 | 状态页 |
| SEV-4 | 轻微问题、无用户影响 | 下一个工作日 | 内部记录 |

### 5.2 响应流程

检测 → 定级 → 止损（熔断/禁用供应商/暂停发布）→ 取证与遏制 → 恢复 → 用户救济（故障返还/重试/退款）→ 复盘（结构化时间线、根因、行动项）→ 控制改进。

- 复盘不含用户正文内容；破窗取证按 SEC-007。
- P0 风险相关事故未关闭前禁止发布（RELEASE-CHECKLIST 守门）。

## 6. 关键规则（红线）

1. 零容忍：严重泄露、越权访问、重复扣费、评分证据丢失——上线与运营均为 0 目标。
2. 后台无任何改分入口；敏感内容访问只有"用户授权"与"破窗"两条路径，全部审计。
3. 密钥只进密钥管理系统；仓库、日志、后台零明文。
4. 最小权限 + 默认拒绝；跨用户/机构/数据区访问例外必须授权且留痕。

## 7. 异常处理

| 异常 | 处理 |
|---|---|
| 密钥疑似泄露 | 立即轮换、吊销受影响令牌、审计使用记录、按 SEV 分级响应 |
| 审计写入失败 | 阻断相应敏感操作（fail-closed）并告警 |
| 恶意文件绕过检测 | 隔离解析环境兜底（无出站网络、一次性沙箱）；样本入回归库 |
| 破窗流程被滥用 | 事后复核发现即 SEV-1 级内部事件处理并加固审批链 |
| 区域边界配置错误 | 部署校验失败即中止发布；运行期发现立即阻断通路并审计 |

## 8. 验证方式

1. 每条 SEC 需求的验证方式列于第 4 节表中，纳入 ACCEPTANCE-MATRIX 的 security 层级。
2. 上线守门：渗透测试、恢复演练、PIA/AI 风险评估、日志扫描全部通过（Pre-Launch Hard Gates）。
3. 持续：季度恢复与删除演练、半年供应商/数据库/积压/区域故障演练、每月公平性与日志扫描。
