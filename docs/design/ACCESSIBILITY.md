# 无障碍规范（ACCESSIBILITY）

| 字段 | 内容 |
|---|---|
| 文档编号 | DESIGN-003 |
| 版本 | 0.1.0（草案，待 Accessibility Lead 评审） |

| 一致性锚点 | `ai/schemas/turn-evidence.schema.json`（accommodations_in_effect 枚举）、`docs/ai/SCORING-SPEC.md`（便利设置不进入评分证据）、`docs/design/SCREEN-SPEC.md` |

## 1. 目的

保证面个蛋全部核心流程对使用键盘、屏幕阅读器、字幕、文字输入或合理便利的用户完整可用，并确保**合理便利永远不进入负面评分**。

## 2. 范围

- WCAG 2.2 AA 合规范围：求职者端全部核心流程（注册登录、材料上传与校对、计划、实时面试房间、结果与报告、练习、资产、购买、隐私），机构端与运营后台的可用性基线。
- 面试便利设置（accommodations）的定义、冻结规则与评分隔离。
- 中文与英文两个语言版本的无障碍验证。

## 3. 非目标

- 不承诺 AAA 级合规（AA 为发布门槛，AAA 项作为持续改进）。
- 不做手语准确度、情绪或人格的自动评分（PRD 明确禁止；手语用户可使用摄像头，文字作为正式评分证据）。
- 不定义医疗或法律意义上的残障认定流程——系统不推断具体残障，只记录"使用了便利模式"。

## 4. WCAG 2.2 AA 要求清单

### 4.1 感知

| 要求 | 实现要点 |
|---|---|
| 对比度 | 正文 ≥4.5:1、大文本 ≥3:1；语义色板在 CI 校验（见 DESIGN-SYSTEM） |
| 非颜色唯一提示 | 通过/未通过/评估未完成三态均有图标+文字；错误不只变红；雷达图不只靠颜色分区 |
| 缩放 | 200% 及以上缩放无内容丢失、无横向滚动（房间页允许工具区内部滚动） |
| 图表等价 | 雷达图、趋势图、岗位匹配图必须同时提供**文字与表格等价版本**（report.schema.json 的 text_equivalent 字段为强制） |
| 字幕与逐字稿 | 数字人实时字幕、完整文字流、问题固定显示（可回看）、可下载逐字稿；字幕开关常显 |
| 减少动态效果 | 尊重 `prefers-reduced-motion`；数字人以外的装饰动画可关闭 |

### 4.2 操作

| 要求 | 实现要点 |
|---|---|
| 键盘 | 全部功能键盘可达：房间控制条（麦克风/摄像头/停止数字人/文字输入/提交）、工具区（代码编辑器、白板提供键盘替代操作）、结果页操作 |
| 焦点 | focus-visible 清晰可见；弹窗焦点圈定与返回；打断/停止按钮在 Tab 序前段 |
| 时间 | 延长时间、调整静默阈值等设置见第 5 节；会话超时前有警告与延长路径（认证超时走 AUTH_PAUSED 不计时不判失败） |
| 目标尺寸 | 指针目标 ≥24×24 CSS px（AA 2.2 新增）；主要控制 ≥44px |

### 4.3 理解

| 要求 | 实现要点 |
|---|---|
| 可读性 | 错误提示五要素（影响/数据保留/重试/计费/评分影响）用平实语言，中英文分别撰写而非机翻 |
| 一致导航 | 状态术语与状态机枚举一致（DRAFT…COMPLETED 的用户可见文案固定） |
| 输入协助 | 表单错误定位到字段；解析校对页低置信度字段高亮并说明 |

### 4.4 健壮

- 语义化 HTML；房间状态变化、新字幕、回合推进使用 `aria-live` 区域（字幕区 `aria-live="polite"`，故障与降级提示 `role="alert"`）。
- 屏幕阅读器语义：数字人视频区标注"数字面试官视频（始终开启）"；候选人摄像头区标注开关状态；工具区角色化（editor/whiteboard/case/portfolio）。

## 5. 面试便利设置（Accommodations）

### 5.1 设置清单（枚举与 turn-evidence.schema.json 一致）

| key | 名称 | 说明 |
|---|---|---|
| `text_only` | 纯文字模式 | 全部作答以文字提交；口语表现标记"未评估"，**不记零、不扣分** |
| `mixed_input` | 混合输入 | 语音/文字/工具自由切换，按实际有效证据评分 |
| `slower_avatar_speech` | 降低数字人语速 | TTS 语速下调 |
| `repeat_questions` | 重复问题 | 可要求数字人重复问题 |
| `extended_time` | 延长思考/回答时间 | 延长回合计时与静默判定 |
| `silence_threshold_adjusted` | 调整静默阈值 | 自定义静默判定时长 |
| `no_proactive_interruption` | 禁止主动打断 | 数字人不主动礼貌打断 |
| `reduced_motion` | 减少动画 | 关闭非必要动效 |
| `tool_keyboard_alternative` | 工具键盘替代 | 白板/代码等工具的完整键盘操作路径 |

### 5.2 生命周期规则

1. **会前可选**：SCR-06/SCR-07 提供便利设置入口，默认全部关闭，逐项独立开启（不使用捆绑或诱导）。
2. **开始后冻结**：正式面试开始后不可修改；唯一例外是系统故障（如数字人故障降级文字，属故障流程而非设置变更）。
3. **跨轮继承**：同一项目后续轮次继承已冻结设置，用户可在轮次间隙的会前检查中调整下一轮（新一轮开始前重新冻结）。

## 6. 评分隔离红线（不可协商）

1. **便利设置不进入评分证据**：`accommodations_in_effect` 仅作记录，评分服务的输入不包含任何便利惩罚项（SCORING-SPEC 6.4）。
2. **文字模式**：沟通维度 = 结构与清晰度归一化得分；口语表现 `not_evaluated`，不记 0 分；报告明确标注输入模式及证据限制。
3. **摄像头关闭不影响任何分数**；手语用户可使用摄像头，但系统不做手语准确度、情绪或人格评分，文字作为正式评分证据。
4. **报告只记录"使用了便利模式"，不推断具体残障**；便利模式指标只用于公平性切分监测（防止平均值掩盖局部退化），不展示给机构。
5. 指标按输入模式与便利模式切分（PRD Guardrails），任何切分的显著退化触发评分公平性复测。

## 7. 关键规则汇总

1. WCAG 2.2 AA 是 **Pre-Launch Hard Gate**：中文与英文核心流程分别达到才算通过。
2. 雷达/趋势/匹配图必须提供文字与表格等价版本；字幕、完整文字流、问题固定显示、可下载逐字稿为强制。
3. 便利设置会前可选、开始冻结、不进入评分；文字不记零。
4. 不使用暗黑模式；便利设置入口与授权中心一样独立、清楚、可撤回。

## 8. 异常处理

| 异常 | 处理 |
|---|---|
| 字幕服务降级 | 保留完整文字流与逐字稿；提示用户字幕暂时不可用但不中断面试（文字流为兜底通道） |
| 辅助技术与房间控件冲突 | 提供"基础模式"开关：隐藏装饰性区域、纯语义化房间布局 |
| 屏幕阅读器下工具不可用 | 工具键盘替代路径；仍不可用时可选择跳过该工具题（按未覆盖点规则处理，不判失败） |
| 便利设置与故障降级叠加 | 降级文字后自动按 text_only 的评分规则处理，报告同时标注降级原因与便利模式 |

## 9. 验证方式

1. **自动化**：axe（或同等）接入 CI，核心页面 0 严重违规；对比度令牌校验。
2. **键盘走查**：SCR-02 ~ SCR-15 全流程仅键盘完成（含一次完整模拟面试的文字模式路径）。
3. **屏幕阅读器**：中英文分别走查（NVDA/VoiceOver 各至少一种），覆盖房间 aria-live 行为。
4. **残障用户可用性测试**：发布前完成（PRD 硬性要求），样本覆盖视觉、听觉、肢体、神经多样性用户。
5. **评分隔离回归**：便利设置开启/关闭的同内容作答评分一致（差异在评分稳定性容差内）；文字模式 oral_delivery 输出为 not_evaluated 的契约测试。
