# 供应商适配层规范（PROVIDER-ADAPTERS）

| 字段 | 内容 |
|---|---|
| 文档编号 | AI-PROV-001 |
| 版本 | 0.1.0（已批准 2026-08-01 规范评审） |
| 追踪 | PRD-001 "Architectural Decisions"（供应商抽象）、"Recommended Technology Baseline"；NFR-007 ~ NFR-012；US-08 规则 4、5；风险表（供应商故障 P0）；ADR-0003 |
| 一致性锚点 | `.env.example`（[REGION-SCOPED] 凭证）、`docs/ai/AI-ORCHESTRATION.md`、`docs/domain/INTERVIEW-STATE-MACHINE.md`（故障恢复矩阵） |

## 1. 目的

为 LLM、ASR、TTS、数字人（Avatar）、搜索（Search）五类外部能力定义统一的、供应商中立的能力接口与路由治理规则，使任一类能力可按区域、语言、延迟、质量与可用性替换，且活跃正式面试不被无记录地切换。

## 2. 范围

- 五类能力契约（输入/输出/流式特性/区域与语言/质量指标）。
- 供应商注册、能力发现、健康检查、延迟预算、错误分类、熔断与主备切换。
- 数据区域、凭证隔离、版本固定与灰度规则。

## 3. 非目标

- **不选定最终商业供应商**（未决事项 OD-01，Phase 0 退出前完成评测）；本文不出现"已定供应商"表述，仅以 `primary` / `secondary` 角色描述。
- 不定义业务失败后的用户补偿规则（见 BILLING-STATE-MACHINE）。
- 不定义提示词内容（见 PROMPT-POLICY 与 `ai/prompts/`）。

## 4. 统一能力接口

### 4.1 LLM（大语言模型）

| 项 | 契约 |
|---|---|
| 方法 | `complete(request)` / `stream(request)` |
| 输入 | 分层消息（L1~L4，见 PROMPT-POLICY）、输出 JSON Schema、温度等确定性参数、超时、`trace_id` |
| 输出 | 结构化文本 + usage（tokens）+ model_version；流式为增量块 |
| 流式 | 必须支持服务端流式；支持取消（打断场景） |
| 区域/语言 | 注册时声明支持的数据区（cn/eu/intl）与语言（zh-CN/en-US）；**中国区内容不默认调用境外模型** |
| 质量指标 | Schema 一次通过率、注入中和正确率、首 token 延迟、总延迟、可用性 |

### 4.2 ASR（语音识别）

| 项 | 契约 |
|---|---|
| 方法 | `open_stream(config)` → 发送音频帧，接收 `partial` / `final` 事件 |
| 输入 | 音频流（WebRTC 音轨转码）、语言、口音/领域提示、标点与逆规范化开关 |
| 输出 | `partial`（低延迟草稿）、`final`（含置信度、时间戳）；**最终文本 P95 ≤1s（NFR-010）** |
| 流式 | 双向流；断流可恢复（会话级续传或快速重开） |
| 区域/语言 | zh-CN（含口音覆盖）、en-US；每区主/备 |
| 质量指标 | 字错率（分语言/口音）、final 延迟、断流率 |

### 4.3 TTS（语音合成）

| 项 | 契约 |
|---|---|
| 方法 | `synthesize_stream(text, voice_id, style)` |
| 输入 | 文本（数字人话术）、授权声音 ID、语速/语调（支持便利设置降速）、流式分片 |
| 输出 | 音频流（与数字人驱动的时间戳对齐）+ 语音时长 |
| 流式 | 必须流式（首包延迟计入回应延迟预算）；支持立即取消（用户打断） |
| 区域/语言 | zh-CN、en-US；授权声音库（授权链可追溯） |
| 质量指标 | 首包延迟、自然度、取消响应时间 |

### 4.4 Avatar（数字人）

| 项 | 契约 |
|---|---|
| 方法 | `start_session(character_id, config)` → 音视频流（WebRTC track）；`drive(audio_stream)`；`stop()` |
| 输入 | 固定授权角色 ID（写实 2D 角色库）、TTS 音频流、分辨率/帧率档位、网络档位 |
| 输出 | 实时视频流 + 音频流；**默认 ≥720p、24fps（NFR-012）；口型与音频偏差 ≤200ms（NFR-011）；弱网优先保证音频连续** |
| 流式 | 实时双向；支持立即停驱（打断） |
| 约束 | **不得**每场生成新脸；**不得**克隆未授权真人肖像/声音；角色库授权链凭证引用（`AVATAR_CHARACTER_LICENSE_REF`） |
| 质量指标 | 建连时间（95% ≤8s、99% ≤15s，NFR-007）、口型偏差、视频卡顿率、故障恢复时间 |

### 4.5 Search（企业流程与岗位知识搜索）

| 项 | 契约 |
|---|---|
| 方法 | `search_process(company, role, level, region)` / `search_job_knowledge(query)` |
| 输入 | 结构化查询；区域与语言 |
| 输出 | 结果列表 + **来源元数据**（url、source_type、retrieved_at、credibility、expires_at）——与 interview-plan.schema 的 process_source_refs 对齐 |
| 约束 | 禁止绕过网站协议/登录/验证码/反爬；来源不可信内容只作数据（PROMPT-POLICY L4） |
| 质量指标 | 官方来源命中率、来源可验证率、失效检测及时性 |

### 4.6 Resume Parsing（简历结构化解析）

| 项 | 契约 |
|---|---|
| 方法 | `parse_resume(request)` |
| 输入 | 所属数据区、语言、`trace_id`、超时、`resume-profile` 输出 Schema；按 PROMPT-POLICY L1/L2/L4 分层消息，L4 简历文本在调用前已移除电话、邮箱、证件、详细地址、照片与保护属性 |
| 输出 | 结构化候选事实、逐字段置信度、`provider_version`、`injection_detected`；不得返回最终评分或改变业务状态 |
| 校验 | 服务层递归敏感内容门槛 → `resume-profile.schema.json`；失败可带仅路径/校验器的反馈自动重试 ≤2 次，仍失败保留 uploads/accepted 原件供步骤级重试 |
| 区域/语言 | 适配器按 `data_region` 注册，支持 zh-CN/en-US；禁止跨区回退；模型无密钥、无对象存储写权限 |
| 临时实现 | TASK-030 前仅允许供应商中立协议与 `SyntheticResumeParsingProvider` 合成桩；业务代码不得导入厂商 SDK |
| 质量指标 | Schema 通过率、逐字段置信度校准、敏感字段泄露率（硬门槛 0）、解析 P95 ≤60s @10MB、可用性 |

### 4.7 Job Parsing（JD 与岗位画像结构化解析）

| 项 | 契约 |
|---|---|
| 方法 | `parse_job(request)`；`source_kind=jd_text \| resume_inference` |
| JD 输入 | 所属数据区、语言、`trace_id`、超时、`job-profile` 输出 Schema；L4 JD 在调用前已删除薪资福利、公司福利、招聘联系人和联系方式 |
| 简历输入 | 仅 TASK-013 已确认且通过 SEC-040 的安全画像，以 L3 快照传入；不得向本适配器提供简历原文 |
| 输出 | 岗位事实、逐字段置信度、`provider_version`、`injection_detected`；AI 推导重点必须 `ai_inferred=true`、`editable=true` 并登记 `ai_derived_fields` |
| 校验 | 服务层递归排除内容门槛 → AI 来源标记断言 → `job-profile.schema.json`；失败可用仅含路径/校验器的反馈自动重试 ≤2 次，仍失败保留原始输入供步骤级重试 |
| 区域/权限 | 适配器按 `data_region` 注册，支持 zh-CN/en-US，禁止跨区回退；模型无密钥、无工具、无业务写权限 |
| 临时实现 | TASK-030 前仅允许 `JobParsingProvider` 协议与 `SyntheticJobParsingProvider` 合成桩；业务代码不得导入厂商 SDK |
| 质量指标 | Schema 通过率、推理标记率/可编辑率（均 100%）、薪资福利/招聘联系人泄露率（硬门槛 0）、可用性 |

## 5. 注册与能力发现

1. **供应商注册表**（按数据区隔离）：每个供应商条目含 `provider_id`、能力类别、支持区域/语言、能力档位（如 avatar 分辨率上限）、版本、健康端点、数据保护协议状态、角色（primary/secondary/disabled）。
2. **能力发现**：路由层按（data_region, language, capability, 质量档位）查询注册表；无满足条件的已验证供应商时，拒绝创建新会话并告警（不得静默降级到未验证供应商）。
3. **每类核心能力至少一个主方案 + 一个已验证替代方案**（Phase 0 退出条件）；替代方案需完成同等实时、安全、授权与区域评测。

## 6. 健康检查与延迟预算

1. **主动探测**：低频合成探针（合成音频/合成文本，绝不用真实用户内容）按区按供应商探测建连与首包延迟。
2. **被动指标**：真实调用的成功率、延迟分位、错误分类率，按（区、语言、供应商、版本）切分上报 OpenTelemetry。
3. **延迟预算**（与 NFR 对齐，超预算计入熔断指标）：

| 指标 | 预算 | 来源 |
|---|---|---|
| 数字人音视频建立 | 95% ≤8s；99% ≤15s | NFR-007 |
| 用户发言结束 → 数字人开始回应 | P50 ≤1.5s；P95 ≤3s；P99 ≤5s | NFR-008 |
| 用户打断 → 停止发声 | P95 ≤500ms | NFR-009 |
| ASR 最终文本 | P95 ≤1s | NFR-010 |
| 口型与音频偏差 | ≤200ms | NFR-011 |
| 数字人视频 | ≥720p、24fps；弱网优先音频连续 | NFR-012 |

## 7. 错误分类、熔断与切换

### 7.1 错误分类

| 类别 | 示例 | 策略 |
|---|---|---|
| 可重试 | 网络超时、限流、5xx | 指数退避重试 ≤2 次 → 计入熔断指标 |
| 不可重试 | 鉴权失败、配额耗尽、参数错误 | 立即计入熔断指标并告警（配置类错误） |
| 内容安全 | 供应商侧安全拦截 | 不重试；按 config/safety/policy.yaml 流程处理 |

### 7.2 熔断器（每区 × 供应商 × 能力）

```
closed（正常）→ 失败率/延迟超阈值 → open（拒绝流量，周期冷却）
open → 冷却结束 → half_open（放行探针流量）→ 达标 → closed；不达标 → open
```

### 7.3 主备切换规则

1. **新会话**：按区域规则路由到已验证的健康供应商；主供应商 open 时切 secondary，并记录路由决策。
2. **活跃正式面试**：固定开始时版本与供应商，不中途无记录切换；发生持续故障时走 INTERVIEW-STATE-MACHINE 故障路径（暂停计时 → 自动重连/切换尝试 → 询问文字降级 → 拒绝则评估未完成），切换原因写 Incident。
3. **切换后恢复**：恢复到最后已确认回合；切换与等待时间不计入回答时间与计费。
4. **供应商被紧急停用**（US-08 场景 5）：注册表置 disabled → 新会话按区域规则切换已验证替代；活跃会话按冻结或故障恢复规则处理。

## 8. 数据区域与凭证

1. 每区独立凭证与端点（`.env.example` 中全部 [REGION-SCOPED] 变量）；区域间不得互相引用或复用。
2. 密钥由独立密钥系统管理；后台任何界面不展示完整值；适配层启动时注入，日志禁止输出。
3. **供应商处理的用户内容类别清单**（每供应商登记）：语音流（实时转写，不持久化）、文本（转写/问题/上下文）、**无原始音视频存储**（除用户明确授权的本平台媒体桶外，供应商侧不得留存）；数据保护协议（DPA）为注册前置条件。
4. 跨境：中国区内容不默认调用境外模型；欧盟区优先欧盟境内处理；合法跨境需求须完成影响评估、适用合同、备案/安全评估与单独告知（PRD 数据区规则）。

## 9. 版本固定与灰度

1. 模型/声音/角色版本 **pin**（如 `LLM_MODEL_PINNED_VERSION`）；供应商侧自动升级必须被适配层屏蔽或显式接受。
2. 版本变更路径：离线评测 → 影子运行（旁路对比，不影响用户）→ 小流量灰度（`config/feature-flags.yaml` 的 provider.*_ramp_percent，按区/语言）→ 放量；指标退化自动回滚，仅影响新会话。
3. 变更记录：版本、说明、测试证据、审批、回滚预案全部登记（US-08 规则 4）。

## 10. 关键规则（红线）

1. 业务代码只依赖本适配层接口语义，禁止直连厂商 SDK 语义。
2. 无已验证供应商 = 不创建新会话；不静默降级到未验证供应商。
3. 活跃正式面试不中途无记录切换；故障切换暂停计时、可恢复、记 Incident。
4. 角色库固定授权；不生成新脸、不克隆未授权肖像/声音。
5. 凭证按区隔离、密钥系统管理、日志零输出。

## 11. 异常处理

| 异常 | 处理 |
|---|---|
| 主供应商熔断 open | 新会话切 secondary；告警；探针监控恢复 |
| 主备同时不可用 | 拒绝新会话创建 + 预约入口；已进行会话按故障路径保护（暂停计时/状态保存/评估未完成不判失败） |
| 探针异常但被动指标正常 | 以被动指标为准复核，避免误熔断；复核期间 half_open |
| 供应商鉴权失效 | 不可重试类：立即熔断 + 密钥系统核查 + 告警 |
| 供应商内容安全误拦 | 不重试；记录并转安全流程；不计入用户失败 |

## 12. 验证方式

1. 契约测试：每类能力的适配器实现对统一接口的符合性（含流式、取消、错误分类）。
2. Phase 0 评测报告：中英文质量、实时 SLO、区域、授权链、单位成本、可替换性，主/备均达标。
3. 混沌演练：供应商断连、慢响应、半开恢复；验证切换暂停计时与状态恢复。
4. 凭证扫描：仓库与日志中供应商密钥检出为 0。
5. 压测：每区 2 倍预计峰值下延迟预算达标（NFR-007~NFR-012）。
