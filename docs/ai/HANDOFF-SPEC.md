# 跨轮交接规范（HANDOFF-SPEC）

| 字段 | 内容 |
|---|---|
| 文档编号 | AI-HANDOFF-001 |
| 版本 | 0.1.0（草案，待 AI/评分负责人评审） |
| 追踪 | PRD-001 "Cross-Round Handoff"、"Retry and Dimension Locking"；US-02 规则 12；US-04 规则 8；FR-011、FR-012 |
| 一致性锚点 | `ai/schemas/handoff-package.schema.json`（结构事实源）、`docs/ai/SCORING-SPEC.md`、`docs/domain/INTERVIEW-STATE-MACHINE.md` |

## 1. 目的

定义后一轮数字面试官接收的冻结上下文（HandoffPackage）的结构、生成、压缩与事实完整性规则，保证"后一轮必须获得简历、JD、前序轮次纪要、评价、风险、已验证能力和未覆盖点"这一 PRD 硬性规则可执行、可测试。

## 2. 范围

- HandoffPackage 的字段语义、生成时机、注入面试官决策图的方式。
- 最大上下文预算、摘要压缩算法约束与事实完整性校验。
- 禁止重复问题与允许重新验证的执行规则。

## 3. 非目标

- 不定义追问语言风格（见 `ai/prompts/` 实时面试官契约）。
- 不定义评分算法（见 SCORING-SPEC）；交接包只传递评分结论与证据引用，不参与计算。
- 不向用户提前泄露后续轮次的正式考点或完整标准答案。

## 4. 生成时机与触发

| 时机 | 触发事件 | 说明 |
|---|---|---|
| 轮次通过 | `round_result_published`（PASS）且仍有后续轮 | 生成 to_round = 下一轮的交接包；项目状态回到 READY |
| 正式重试通过 | 重试轮 PASS 且仍有后续轮 | 交接包必须反映最新有效 ScoreVersion（含锁定维度沿用分） |
| 生成失败 | 交接包生成失败 | 下一轮禁止开始（`handoff_package_ready` 前置条件不满足），只重试交接生成，不影响已有评分 |

第 1 轮无交接包；第 n 轮（n ≥ 2）开始前必须存在 `to_round_sequence = n` 的交接包。

## 5. 内容规则（与 Schema 字段一一对应）

### 5.1 必须包含（PRD 硬性规则）

1. **简历结构化事实快照**（`resume_snapshot_ref`）：面试上下文安全版，绝不含电话、邮箱、证件、地址、照片、保护属性。
2. **JD 结构化要求快照**（`job_snapshot_ref`）：含必备/加分要求与权重。
3. **前序轮次纪要**（`rounds_history`）：从第 1 轮到前一轮的问题、回答摘要、追问、未回答项与工具行为。
4. **评价**（`dimension_scores`、`strengths`、`weaknesses`）：各维度得分、锁定状态与通过状态。
5. **风险**（`risks`）：待验证风险（如简历线索未澄清、回答与简历不一致）。
6. **已验证能力**（`verified_capabilities`）：锁定维度与已证明 JD 要求。
7. **未覆盖点**（`uncovered_points`）：进入后续轮次补问与重试范围。
8. **禁止重复问题**（`do_not_repeat_questions`）与**允许重新验证**（`allowed_reverification`）。

### 5.2 失败点与矛盾

- `failed_points`：未达 60 维度的摘要 + 证据引用；后续轮次针对失败点深入（不重复原题）。
- `contradictions`：已识别的前后矛盾（证据引用成对）；后续轮次可围绕矛盾验证，属 `allowed_reverification` 的 `direct_contradiction` 情形。
- `follow_up_focus`：由交接生成器按固定优先级产出——① 未覆盖点补问；② 风险验证；③ 弱项更深入（不重复已通过相同问题）；④ 建议难度（`suggested_difficulty`）。

### 5.3 禁止重复与例外（执行层强制）

- 面试官决策图在生成主问题时必须对 `do_not_repeat_questions` 做语义去重；命中的候选问题一律丢弃并重选。
- 仅当出现以下两种例外允许重新验证同一主题（仍不用相同措辞）：
  - `direct_contradiction`：新证据直接矛盾于已通过回答；
  - `new_job_scenario_transfer`：新的岗位场景需要迁移验证。
- 度量：新题遵守不重复已通过原题规则的比例 ≥ 95%（PRD 90 天目标，评测集回归）。

## 6. 上下文预算与压缩

| 参数 | 初始值 | 说明 |
|---|---|---|
| `max_tokens` | 6000 tokens | 注入面试官决策图的交接包上限（随模型上下文窗口调整，属部署配置） |
| 压缩优先级 | 见下 | 超预算时按优先级丢弃或进一步压缩，**不得删除 5.1 的 1/2/7/8 四类** |

压缩顺序（从最先压缩到最后）：

1. `rounds_history.questions[].answer_summary`：逐题摘要压缩至 ≤ 120 字（中文）/ ≤ 80 词（英文），保留量化结果与矛盾点；
2. `followups` 合并为一句追问链摘要；
3. 较早轮次的 `strengths/weaknesses` 去重合并；
4. 仅保留各维度最新有效得分与锁定状态（历史版本以引用表示）。

### 事实完整性规则（强制校验）

1. **不引入新事实**：摘要不得包含原证据中不存在的实体、数字或结论（`factual_integrity.no_new_facts`）。
2. **可回溯**：每条摘要必须保留证据引用（`source_refs_complete`）；无法回溯的句子删除。
3. **用户事实 / AI 推理 / 外部来源三分离**：交接包中 AI 推导内容沿用 `ai_inferred` 标记；外部来源沿用 `process_source_refs` 标记。
4. **敏感字段零携带**：校验器扫描交接包，命中敏感字段类别（手机号模式、邮箱模式、证件号模式等）即拒绝生成并告警。
5. 校验失败 → 交接包不生效，下一轮不可开始，触发重试与告警。

## 7. 与评分/状态机的交互

- 交接包引用 ScoreVersion 而非复制分数；重试产生新版本后，后续交接包必须反映最新有效版本。
- 锁定维度在交接包中标记 `locked: true`；若后续轮次新证据与锁定证据矛盾，面试官记录矛盾事件并交由评分服务按 SCORING-SPEC 6.7 处理——**面试官不得自行改分**。
- 项目状态 `ROUND_PASSED → READY` 迁移的前置条件之一：交接包生成且校验通过。

## 8. 关键规则（红线）

1. 后一轮必须收到 5.1 全部八类内容；缺一禁止开始该轮。
2. 已通过的相同问题不重复；例外仅 `direct_contradiction` / `new_job_scenario_transfer`。
3. 交接包永远不含敏感字段、不含后续轮次正式考点答案、不含保护属性。
4. 压缩不得牺牲事实完整性；无法回溯的内容删除而非猜测。
5. 交接包是只读上下文：面试官可据其调整提问，但业务状态（分数、解锁、额度）只能由工作流与评分服务改变。

## 9. 异常处理

| 异常 | 处理 |
|---|---|
| 交接生成模型超时/失败 | 重试失败模块；下一轮保持不可开始；不影响已完成评分 |
| 事实完整性校验失败 | 拒绝该交接包；记录校验项；重新生成（≤3 次）后升级人工 |
| 敏感字段扫描命中 | 拒绝生成 + 安全告警；排查上游摘要链路 |
| 前序 ScoreVersion 被复核更新 | 交接包标记过期并重新生成（引用式分数保证不重算） |

## 10. 验证方式

1. 结构校验：`ai/evals/datasets/` 中交接样例通过 `handoff-package.schema.json` 校验。
2. 规则测试：语义去重命中率、压缩后事实完整性校验、敏感字段扫描的单元与集成测试。
3. 评测回归：不重复规则遵守率 ≥ 95%；交接完整性（八类内容齐全）= 100%。
4. 端到端：第 2、3 轮开始前置检查阻断测试（缺交接包不得开始）。
